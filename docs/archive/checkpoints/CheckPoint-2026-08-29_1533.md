### 2. Fixed `diagram_tier_accounts_table` column widths (`bf59f2f`)

Per explicit user spec: Tier 15% / Cloud Account IDs 70% / Pick Accounts
15% of the table's own width. New `_PercentColumnTableWidget` (a
`QTableWidget` subclass recomputing column widths on `resizeEvent`/
`showEvent`) replaces the plain `QTableWidget` + `setStretchLastSection`
this table used before.

### 3. Fixed the real root cause of "Tier column shows Tier 1 for every
   row" (`bf59f2f`)

The user's UI bug report was real and reproducible, but not a code bug --
`_sync_diagram_tier_table`/`_parse_tier_lines` were already correctly
tested. The actual cause: Salvo Metal Works' own
`chimney_shrouds.yaml` had "YACSS Tiers (tier:pages, one per line)"
literally saved as `1:1` / `1:6` / `1:1` (every line typed with tier
number `1` instead of incrementing), which correctly (if unhelpfully)
exported three `{"tier": 1, ...}` rows. Fixed the data directly in the
sibling project, and added a `save_yaml` validator here that now blocks
(via `QMessageBox.warning`, naming the offending tier number(s)) on any
duplicate tier number, so this can't silently corrupt an export again.
New regression test `test_save_yaml_blocks_on_duplicate_tier_numbers`.

### 4. Added anchor-text backlink fields (`266ff52`)

A live-published `rr_yacss_factory` build (`salvo-metal-works`, id
`127752`) confirmed `landing_url` alone only ever produces a
`<link rel="canonical">` tag in the published page -- no real, visible
citation backlink, which is the entire point of a `cloud_stack` build.
The real YACSS dashboard form pairs its "Target Url" field with "Text
before/of/after target link" fields to actually weave one in.
`rr_yacss_factory`'s `CloudStackJob` gained three new required fields
(`target_link_text_before`/`target_link_text`/`target_link_text_after`,
schema.ts v1.14) to match. Added corresponding Diagram-only, required
UI fields here ("YACSS Text Before/Of/After Target Link"), following the
same required-field warning pattern `* Website` already uses. Applied
the user's real values for the Salvo chimney-shrouds job (before:
"Visit", anchor: "Salvo Metal Works", after: "to learn more about Custom
Chimney Shrouds") to `client_yaml/salvo_metal_works/chimney_shrouds.yaml`
(gitignored) -- round-trip verified via a real `load_yaml()` call, no
warnings.

**Live-verified this fix does not actually work server-side** (from the
`rr_yacss_factory` side, build `127756`): the fields submit and store
correctly in the build's own config, but YACSS never renders them into
the published page. A genuine platform bug, not fixable from either
project -- see the sibling project's checkpoint for the full evidence
trail and the drafted support ticket.
