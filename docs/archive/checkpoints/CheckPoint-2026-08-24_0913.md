# Checkpoint - 2026-08-24_0913

## Context summary

Follow-up session to 2026-08-21's YACSS build-settings work. Three
separate asks this session: (1) split the "one per line" text fields into
real YAML lists at save time, a known issue flagged in the prior
checkpoint; (2) a UI bug report -- the Services field (and by the same
root cause, other QTextEdit fields) rendering white text on a white
background under Windows dark mode, though the underlying YAML data was
saving correctly; (3) set up a real pytest suite, since investigation
showed the project had no test framework at all (no pytest in
requirements, no test config, only ad-hoc offscreen smoke tests written
and discarded per session).

## Accomplishments

- `main.py`: added `YAMLForm.LIST_FIELDS` (a class-level set naming
  `* Target Cities (one per line)`, `* Services (one per line)`,
  `Social/Citation URLs (one per line)`, `FAQ Questions (one per line)`).
  `save_yaml()` now splits those four fields' `QTextEdit` text into a real
  YAML list (blank lines and per-line whitespace stripped) instead of
  writing the raw multi-line string. `load_yaml()` was made to accept
  either format: if the loaded value is a list it's rejoined with `\n`
  before being placed back in the widget, so older YAML files saved in
  the previous flat-string format still load correctly.
- Fixed a white-on-white text bug: neither `main.py` nor
  `city_embed_dialog.py` had ever set an explicit palette/stylesheet on
  any input widget, so `QTextEdit` fields (unlike `QLineEdit`) could
  inherit a mismatched text/background color pair from a Windows
  dark-mode palette in PyQt6, rendering stored (and otherwise-correct)
  text invisibly. Fixed by setting an explicit
  `QLineEdit, QTextEdit { background-color: white; color: #000000; }`
  stylesheet on `main.py`'s `central_widget` (cascades to all form
  inputs) and on `CityEmbedDialog` itself (its own separate top-level
  widget, so needed its own rule).
- Added a real pytest suite: `conftest.py` (root) provides a
  session-scoped `qapp` fixture -- offscreen `QApplication`, forced via
  `QT_QPA_PLATFORM=offscreen` set before PyQt6 is imported -- plus an
  autouse fixture that stubs `QMessageBox.information/critical/question`
  so tests never block on a real modal dialog. `tests/test_save_load_roundtrip.py`
  (6 tests) covers: save splits the four list fields correctly (including
  blank-line/whitespace handling and the all-empty case); non-list fields
  stay plain strings on save; load reads the new list format; load reads
  the legacy flat-string format (backward compat); and a full
  save-then-reload round trip including `city_data`/`city_embeds`. All
  tests monkeypatch `QFileDialog.getSaveFileName`/`getOpenFileName` to a
  `tmp_path` file rather than touching the real file-picker dialog.
  Verified the suite actually catches regressions by temporarily
  reverting the list-splitting logic in `save_yaml()`, confirming 2 of 6
  tests fail as expected, then restoring the correct code and confirming
  all 6 pass again (`git diff main.py` empty afterward).
- Added `requirements-dev.txt` (`-r requirements.txt` + `pytest`) so the
  runtime `requirements.txt` stays free of dev-only dependencies;
  installed pytest into the project's canonical `venv/` (the one
  `README.md`/`test.cmd` document, distinct from an also-present but
  undocumented `.venv/`). Added a "To run tests" section to `README.md`.
  Added `.pytest_cache/` to `.gitignore`.
- Commits, both pushed to `origin/main`:
  - `b9569b1 feat: save one-per-line fields as YAML lists; fix white-on-white text`
  - `016670c test: add pytest suite for save/load YAML round-tripping`

## Known issues

- Two virtual environments exist in the repo root: `venv/` (documented in
  `README.md`/`test.cmd`, canonical) and `.venv/` (undocumented,
  different PyQt6 patch version -- 6.10.1 vs 6.9.1 -- used ad hoc for
  offscreen smoke tests in prior sessions). Not cleaned up this session;
  both are gitignored so this is cosmetic/local-disk clutter only, not a
  repo-state problem, but worth consolidating to avoid confusion about
  which one is "the" project environment.
- The white-on-white fix hardcodes light-theme colors (white background,
  black text) rather than reading/following the OS theme. This matches
  the app's existing total absence of any dark-mode support (the
  `self.dark_mode` attribute set in `__init__` has never been read
  anywhere in the codebase -- it's dead/vestigial). A real dark-mode
  toggle was out of scope for this bug fix; flagging in case the vestigial
  attribute causes confusion later.
- The new pytest suite covers only `save_yaml`/`load_yaml` round-tripping.
  It does not cover `CityEmbedDialog`'s own validation
  (`validate_and_accept`), the "missing embeds" warning branch in
  `save_yaml()` (deliberately sidestepped in tests via the autouse
  `question` stub defaulting to "No"), or any UI/visual regression (e.g.
  the white-on-white bug itself isn't something a headless pytest run can
  detect -- it was diagnosed and fixed by code inspection, not by a test).
