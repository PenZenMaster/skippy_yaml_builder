# Checkpoint - 2026-08-26 19:30

## Context summary

Built out Salvo Metal Works' full client YAML config set (a general
company page plus one file per product category), then made three
build-mechanics fields more "meat sack friendly" per the user's own
framing: `YACSS AI Platform`/`YACSS AI Model`/`YACSS Tone` converted from
free-text guessing to live dropdowns, and Diagram tier cloud accounts
gained a named picker instead of requiring a raw numeric ID to already be
known. Later in the session (working in the sibling `rr_yacss_factory`
repo, but the fix applies equally here since this project keeps an exact
Python port of the same formula) a real live test of the Salvo Metal
Works build surfaced a genuine math bug in
`_compute_cloud_stack_total_pages`, fixed here too.

## Accomplishments

1. **Salvo Metal Works client YAML configs**, in
   `client_yaml/salvo_metal_works/`: `general.yaml` (company-wide,
   "Custom Architectural Metal Fabrication") plus one file per product
   category -- `chimney_shrouds.yaml`, `cupolas.yaml`, `dormers.yaml`,
   `finials.yaml`, `leader_boxes.yaml`, `roof_vents.yaml`,
   `specialty_products.yaml`, and `snow_guards.yaml` (renamed from the
   pre-existing `client_profile.yaml` for naming consistency with the
   rest). Each has its own 11-question FAQ set (5 originally drafted +
   6 from a `faq_by_catagory.csv` the user supplied) grounded in real
   facts pulled from salvometalworks.com's own product pages. Caught and
   fixed one real bug along the way: a `#15` in one snow-guards FAQ
   answer was silently truncating that YAML file at parse time (YAML
   treats ` #` as a comment start inside a plain scalar) -- reworded to
   "No. 15" and reconfirmed the file parses cleanly.

2. **`YACSS AI Platform`/`YACSS AI Model`/`YACSS Tone` are now live,
   editable dropdowns**, not free-text `QLineEdit`s -- the user's own
   framing was that guessing valid values required having YACSS's own
   dashboard open in another window. AI Platform populates from `GET
   /ai-providers` (configured accounts sorted first; unconfigured ones
   still shown, just tooltip-flagged, since they may be configured on a
   different account or later); AI Model populates from `GET
   /ai-models`, filtered live to whichever platform is currently
   selected. Tone is pre-filled with the one real enum this project has
   ever confirmed (`Conversational`, `ProfessionalWarm`, `Authoritative`,
   `Empathetic`, `Witty`, `Inspirational`, `Persuasive`, `Relatable`,
   `Educational`, `Urgent` -- from `rr_yacss_factory`'s own live
   `build-fields?type=listicle` capture). All three stay editable, same
   as the existing `YACSS Template` pattern, so an unlisted/future value
   still round-trips through save/load. `yacss_api.py` gained
   `fetch_ai_providers`/`fetch_ai_models`, mirroring
   `rr_yacss_factory`'s confirmed `listAiProviders`/`listAiModels`.

3. **Diagram tier cloud accounts are now pickable by name.** Cloud
   Account IDs aren't shown anywhere in the YACSS dashboard UI itself --
   previously the only way to know what a given ID referred to was
   `rr_yacss_factory`'s own `factory list-cloud-accounts` in a separate
   window. Each tier row in `diagram_tier_accounts_table` gained a
   "Select..." button (new third column) opening a checkable picker
   (`_CloudAccountPickerDialog`) showing real accounts by
   provider/name/client, matching the existing flat checklist's label
   format. It writes plain comma-separated ids back into the same
   column-1 cell used before, so nothing downstream (`export_job_json`,
   save/load, existing tests) needed to change -- manual entry still
   works as a fallback if the live lookup fails.

4. **Real bug found and fixed: `_compute_cloud_stack_total_pages` never
   multiplied by `tier0_pages`.** Discovered live in `rr_yacss_factory`
   while testing this exact Salvo Metal Works job (see that project's own
   2026-08-26 checkpoint for the full live-verification trail against
   real build ids 127455/127459) -- only ever confirmed against a
   `tier0_pages=1` example, where the bug is invisible. Fixed by seeding
   `running_product` at `tier0_pages` instead of `1`, exactly mirroring
   the TypeScript fix. Added a new test
   (`test_compute_cloud_stack_total_pages_multiplies_by_tier0_pages`)
   plus a tier0=3 case in the existing no-tiers test.

5. Also fixed live, in the real exported job file (not this form's
   generic logic): the Salvo Metal Works `YACSS Bucket Keyword` had
   underscores (`salvo_metal_works_architectural_metal`), which broke
   real bucket creation on Backblaze/Azure/AWS. Switched to hyphens.
   **This form still doesn't validate or warn about this** -- see Known
   Issues.

Full test suite: 90/90 (was 81 at session start; +8 for the dropdown/
picker feature, +1 for the tier0_pages fix). Version bumped to 0.3.4;
`CHANGELOG.md` and `README.md` updated in the same commit as the feature
work.

## Known issues / open items

1. **No validation warns about bucket-unsafe characters** (e.g.
   underscores) in `YACSS Bucket Keyword` -- this form will happily save
   and export a keyword that breaks bucket creation on most providers.
   Cost three live `generate` attempts in `rr_yacss_factory` to diagnose
   by hand this session for Salvo Metal Works. Worth adding a real
   warning (e.g. on the Diagram Build Type path, or a general field
   validator) before the next client batch.
2. Two venvs still present in the repo root (`venv/` canonical vs
   undocumented `.venv/`, different PyQt6 patch version) -- still not
   consolidated, carried over from the 2026-08-24 checkpoint.
