## Accomplishments

- **FAQ generation refactored** (`72b7a61`), fixing three reported
  problems with the FAQ tab's "Generate FAQs from People Also Ask":
  - *Made-up client information:* answers are grounded. The prompt lists the
    only facts the model may state (name, category, cities, services from the
    form, plus legal name, address, phone, email, website) and forbids
    inventing prices, hours, years in business, licences, guarantees,
    statistics; unknowns are answered in general terms.
  - *Fewer FAQs than the number picker:* PAA box expanded (click depth 2),
    extra searches adding each target city (max 4 per click), then any
    shortfall topped up with AI-suggested questions, labelled in the summary
    dialog (row numbers) and by a tooltip on the question cell.
  - *Zero / blank output:* the seed is cleaned before searching
    (`emergency-plumber-dallas-01` -> `emergency plumber dallas`; the raw
    hyphenated bucket name was the likely cause of Google returning no PAA
    box), and answers are requested as JSON with only blanks re-asked (up to
    3 calls), replacing a strict numbered-line regex.
- **Released v1.1.0** (`5bd0c62`): `__version__` 1.0.0 -> 1.1.0, changelog
  released as `[1.1.0] - 2026-09-26`. No change to the YAML or job-file shape.
- All four design decisions were the recommended options, chosen through
  `AskUserQuestion` per the project rule.
- Full gate green: ruff, black, mypy, pytest 264/264 (231 + 33 new).

## Known issues / next session priorities

- **Not verified live.** All FAQ tests use mocks. Run "Generate FAQs from
  People Also Ask" once on a real client and confirm (a) the picker count is
  reached, (b) answers contain no invented facts, (c) no blank answers. If
  the count falls short, tune `PAA_CLICK_DEPTH` / `MAX_PAA_SEARCHES` in
  `faq_generation.py`. The real number of questions returned at click depth
  2 is unknown.
- **Cost per click rose:** up to 4 billed SERP searches plus up to 4 OpenAI
  calls (was 1 + 1).
- JSON mode needs a model supporting `response_format` `json_object`;
  default `gpt-4o-mini` does, plain `gpt-4` would reject it. The `gpt-5*`
  `max_tokens` incompatibility from the earlier checkpoint still applies.
- Answers are still AI output: skim before use. AI-suggested questions are
  not real Google questions.
- No `v1.0.0` / `v1.1.0` git tags yet (not requested).
- Carried over: Content Silo real-client validation; optional image-host
  mismatch warning; deferred direct-WordPress-publish fast-follow; existing
  Diagram clients whose Bucket Keyword contains spaces now warn on export.
- Working practice: write scripted-edit files with care for backslashes: a
  non-raw Python string containing `venv\Scripts\activate` turned `\a` into a
  bell character in `docs/projectStatus.md` this session (caught and fixed
  before commit). Use `chr(92)` or raw strings. Line endings remain mixed
  (CRLF: `main.py`, `ai_content_generator.py`, README, CHANGELOG, status
  doc; LF: `keyword_research_api.py`, `faq_generation.py`, tests); check with
  `tr -cd '\r' < file | wc -c` and avoid `sed -i` on CRLF files.
